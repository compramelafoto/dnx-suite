# Etapa 1b — Ventas: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Darle a un workspace de FotoOffice un catálogo de productos y servicios con fotos, códigos y existencias, y una pantalla de mostrador que cobra y deposita la plata en Caja.

**Architecture:** Módulo nuevo `sales`, con el patrón ya establecido por `cash` y `clients` en la etapa 1a: lógica pura y probada en `lib/sales/`, acceso en dos niveles en `access.ts`, consultas en `repository.ts`, pantallas en `app/(shell)/ventas/` con sus formularios y acciones al lado. La venta no inventa nada propio para el dinero ni para el cliente: deposita con `recordCashMovement` y busca con `findOrCreateClient`. Se suma una tabla **sin `workspaceId`** —el catálogo maestro por código de barras—, la primera de todo FotoOffice, y por eso lleva su propia regla escrita y probada.

**Tech Stack:** Next.js 16.2.1 (App Router, server actions), React 19.2.4, Prisma vía `@repo/db`, PostgreSQL en Neon, vitest (entorno node), TypeScript, Tailwind, lucide-react, R2 para imágenes.

**Spec:** `docs/superpowers/specs/2026-09-14-ventas-productos-servicios-y-caja-de-kiosco-design.md` — leerlo entero antes de empezar. §3.4 (el catálogo maestro guarda identidad, no comercio) y §4.3 (vender nunca se bloquea) son las dos reglas que no se negocian.

## Global Constraints

Valen para **todas** las tareas.

- **Ningún enum de Prisma nuevo.** Estados y tipos van como `String` en el esquema y como unión de literales en TypeScript. El `schema.prisma` lo comparten las cinco aplicaciones de la suite y un enum que no exista en alguna base rompe las escrituras de esa aplicación. Precedentes: `Booking.status`, `Raffle.status`, `CashMovement.kind`.
- **El despliegue NO corre `prisma migrate deploy`.** La migración se aplica a mano y se registra en `_prisma_migrations`. **Va ANTES de desplegar el código**, nunca después: en la etapa 1a un despliegue con las tablas ausentes volteaba el cobro de cualquier workspace.
- **Dinero:** en la base `Decimal(12, 2)`; en el código, **centavos enteros**. La conversión pasa **siempre** por `lib/membership/money.ts` (`decimalArsToMinor`, `minorToDecimalString`, `formatMinorArs`, `parseArsToMinor`), nunca por `Number(decimal)`.
- **Cantidades enteras.** No hay medio trípode. `qty` es `Int`.
- **Aislamiento por workspace:** toda consulta lleva `workspaceId`, **salvo las del catálogo maestro**, que es global a propósito. Como el `where` de un `update` tiene que ser único, la pertenencia se verifica con un `count` aparte **antes** de escribir.
- **Control de acceso en el servidor, en dos niveles:** módulo habilitado para ese workspace, y rol de la persona. Esconder un link del menú es cosmético, nunca control.
- **Textos en castellano rioplatense**, segunda persona del singular. Comentarios en castellano que expliquen el porqué, no el qué.
- **Tests:** vitest en entorno node sobre `lib/**/*.test.ts`. `pnpm test` desde `apps/fotoffice`. Hay **una falla previa, conocida y ajena** en `lib/template-v2/access.test.ts`: si aparece otra, es tuya.
- **Un commit por tarea**, mínimo. Mensaje en castellano, imperativo, explicando el porqué.

```prisma
/// Catálogo maestro de productos, por código de barras. **Compartido por toda la suite.**
///
/// Es la ÚNICA tabla de FotoOffice sin `workspaceId`, y es a propósito: el código de barras
/// de un portarretratos es el mismo en Rosario que en Tokio, así que la identidad de la cosa
/// se puede compartir aunque el negocio no.
///
/// Guarda identidad y NADA de comercio: ni precio, ni costo, ni existencia. Lo que cada
/// negocio cobra es suyo. Si alguna vez alguien agrega acá un campo de plata, está rompiendo
/// la única razón por la que esta tabla puede ser global.
model GlobalProduct {
  id          String  @id @default(cuid())
  /// La llave. Único en todo el sistema.
  barcode     String  @unique
  name        String
  brand       String?
  description String?
  imageUrl    String?

  /// Quién la cargó primero. Para poder preguntarle, no para darle permisos.
  /// Sin clave foránea: la ficha sobrevive aunque ese workspace se elimine.
  createdByWorkspaceId String?
  createdByUserId      Int?
  createdAt            DateTime @default(now())
  updatedAt            DateTime @updatedAt

  products Product[]
}

/// Categoría de producto, definida por cada negocio.
model ProductCategory {
  id          String  @id @default(cuid())
  workspaceId String
  name        String
  order       Int     @default(0)
  isActive    Boolean @default(true)

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  workspace Workspace @relation(fields: [workspaceId], references: [id], onDelete: Cascade)
  products  Product[]

  @@unique([workspaceId, name])
  @@index([workspaceId, isActive])
}

/// Lo que el negocio vende: un producto o un servicio.
///
/// Dos interruptores independientes. `kind` dice qué es —sirve para agrupar y para que el
/// reporte separe la línea—. `tracksStock` dice si hay algo que contar: el trípode sí, la
/// sesión de fotos no, y el cuadro tercerizado tampoco aunque sea un producto. Atarlos
/// obligaría a mentir en uno de los dos.
model Product {
  id          String  @id @default(cuid())
  workspaceId String
  categoryId  String?

  /// PRODUCTO | SERVICIO
  kind String @default("PRODUCTO")
  /// Código interno, el que se inventa cada negocio.
  sku             String?
  /// Código de barras del fabricante. La llave del catálogo maestro.
  barcode         String?
  globalProductId String?

  name        String
  description String?

  priceArs Decimal  @db.Decimal(12, 2)
  costArs  Decimal? @db.Decimal(12, 2)

  tracksStock Boolean @default(true)
  /// Copia; la verdad es la suma de StockMovement. Puede ser negativa: eso es información,
  /// significa que falta cargar una entrada.
  stockQty    Int     @default(0)
  minStockQty Int?

  imageUrl     String?
  supplierName String?
  /// Se desactiva, no se borra: las ventas viejas lo siguen nombrando.
  isActive     Boolean @default(true)

  createdByUserId Int?
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt

  workspace      Workspace        @relation(fields: [workspaceId], references: [id], onDelete: Cascade)
  category       ProductCategory? @relation(fields: [categoryId], references: [id], onDelete: SetNull)
  globalProduct  GlobalProduct?   @relation(fields: [globalProductId], references: [id], onDelete: SetNull)
  stockMovements StockMovement[]
  saleItems      SaleItem[]

  @@unique([workspaceId, sku])
  @@index([workspaceId, isActive])
  @@index([workspaceId, categoryId])
  @@index([workspaceId, barcode])
  @@index([globalProductId])
}

/// El libro de existencias. La cantidad que se muestra es la suma de esta columna.
model StockMovement {
  id          String @id @default(cuid())
  workspaceId String
  productId   String

  /// Firmado: la venta resta, la entrada suma.
  qty    Int
  /// VENTA | ENTRADA | AJUSTE | DEVOLUCION | INICIAL
  reason String

  /// En las entradas: lo que costó esa vez.
  unitCostArs Decimal? @db.Decimal(12, 2)

  sourceModule String?
  sourceRef    String?
  /// Obligatoria de hecho en los ajustes: un ajuste sin explicar no se entiende después.
  note         String?

  createdByUserId Int?
  createdAt       DateTime @default(now())

  workspace Workspace @relation(fields: [workspaceId], references: [id], onDelete: Cascade)
  product   Product   @relation(fields: [productId], references: [id], onDelete: Restrict)

  @@index([workspaceId, createdAt])
  @@index([productId, createdAt])
}

/// Una venta de mostrador.
model Sale {
  id          String @id @default(cuid())
  workspaceId String
  /// Correlativo dentro del workspace.
  saleNumber  Int

  clientId   String?
  occurredAt DateTime
  /// COMPLETADA | ANULADA
  status     String   @default("COMPLETADA")

  subtotalArs Decimal @db.Decimal(12, 2)
  discountArs Decimal @default(0) @db.Decimal(12, 2)
  totalArs    Decimal @db.Decimal(12, 2)

  /// EFECTIVO | MERCADO_PAGO | TRANSFERENCIA | TARJETA | OTRO
  paymentMethod String
  /// El ingreso que generó. Único: una venta deposita una sola vez.
  cashMovementId String? @unique

  note String?
  /// Cuando se facturó por fuera. La facturación propia es la etapa 6.
  externalInvoiceRef String?

  voidedAt       DateTime?
  voidedByUserId Int?
  voidReason     String?

  createdByUserId Int?
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt

  workspace Workspace  @relation(fields: [workspaceId], references: [id], onDelete: Cascade)
  client    Client?    @relation(fields: [clientId], references: [id], onDelete: SetNull)
  items     SaleItem[]

  @@unique([workspaceId, saleNumber])
  @@index([workspaceId, occurredAt])
  @@index([clientId, occurredAt])
  @@index([workspaceId, status])
}

/// Un renglón de la venta.
///
/// `description`, `unitPriceArs` y `unitCostArs` son instantáneas: la venta del año pasado
/// tiene que seguir mostrando lo que se cobró y lo que costó ESA vez, aunque el producto
/// después cambie de nombre o de precio.
model SaleItem {
  id     String @id @default(cuid())
  saleId String
  /// Nulo en un renglón suelto, escrito a mano.
  productId String?

  description  String
  qty          Int
  unitPriceArs Decimal  @db.Decimal(12, 2)
  unitCostArs  Decimal? @db.Decimal(12, 2)
  lineTotalArs Decimal  @db.Decimal(12, 2)
  /// Si el precio se pisó a mano. Para poder explicarlo meses después.
  priceWasOverridden Boolean @default(false)

  createdAt DateTime @default(now())

  sale    Sale     @relation(fields: [saleId], references: [id], onDelete: Cascade)
  product Product? @relation(fields: [productId], references: [id], onDelete: SetNull)

  @@index([saleId])
  @@index([productId])
}
```

- [ ] **Paso 1: Pruebas del código de barras**

Crear `lib/sales/barcode.test.ts`:

```ts
import { describe, expect, it } from "vitest";
import { looksLikeBarcode, normalizeBarcode } from "./barcode";

describe("normalizeBarcode", () => {
  it("saca espacios y guiones que el lector o la persona puedan meter", () => {
    expect(normalizeBarcode(" 779-1234 567890 ")).toBe("7791234567890");
  });

  it("un código vacío es null, no cadena vacía", () => {
    expect(normalizeBarcode("   ")).toBeNull();
    expect(normalizeBarcode("")).toBeNull();
  });

  it("rechaza lo que tiene letras: un código de barras es numérico", () => {
    expect(normalizeBarcode("TRP-12")).toBeNull();
  });

  it("conserva los ceros de la izquierda, que son parte del código", () => {
    expect(normalizeBarcode("0012345678905")).toBe("0012345678905");
  });
});

describe("looksLikeBarcode", () => {
  it("reconoce un EAN-13", () => {
    expect(looksLikeBarcode("7791234567890")).toBe(true);
  });

  it("reconoce un EAN-8 y un UPC-A", () => {
    expect(looksLikeBarcode("12345670")).toBe(true);
    expect(looksLikeBarcode("012345678905")).toBe(true);
  });

  it("un código interno inventado no es un código de barras", () => {
```
